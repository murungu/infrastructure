What the live review found

1. The mobile grid is compact but cramped

At 375px, two cards share the row. Product names, prices, ratings, and three actions compete inside a narrow card. The action labels become very small, and the icon controls are difficult to identify.

2. Product actions miss the touch-target standard

The current joined action bar is 40px high. It falls below the 44 × 44px minimum used by the Arity accessibility rules, especially for the wishlist and compare buttons.

3. Empty stars communicate the wrong thing

Products with no reviews still display five empty stars. The row uses space and can look like a zero-star score. Ratings should appear only when review evidence exists.

4. Desktop products use a narrower rail than nearby sections

The hero and approved category section use the expanded homepage content rail. Featured products still sit inside the legacy 980px wrapper, so the page contracts abruptly before expanding again.

5. The heading is a default isolated page-title pattern

A centred title over a long divider does not connect the section to the catalog. There is no short explanation and no visible route to browse beyond the four featured items.

6. The action hierarchy is too dense

Add to cart, compare, and wishlist receive equal visual treatment in a joined bar. On the homepage, buying is primary and saving is secondary. Detailed comparison remains available deeper in the catalog.

7. Product data is still generic sample content

Computers, a phone, and a gift card do not represent Arity Shop. This is an admin-data issue, not a reason to hardcode products into the theme. The wireframe uses renewable-energy examples only to test the intended content shape.

Recommended direction to approve

  1. Use a left-aligned “Featured products” heading, one short supporting sentence, and a visible “Shop all products” link.
  2. Use the approved homepage rail: 16px mobile gutters, 24px tablet gutters, 32px desktop gutters, and a 1600px wide-screen cap.
  3. Use one compact horizontal card per row at 375px, a 2 × 2 grid at 768px, and a four-column row at 1280px.
  4. Use white cards with 1px hairline borders, 8px radius, no shadows, no decorative red, and a black focus outline.
  5. Keep product image and title as clear links. Do not turn the whole card into one link because the card also contains button actions.
  6. Render ratings only when AllowCustomerReviews is true and TotalReviews > 0. State the five-point scale and review count rather than relying on stars alone.
  7. Use a 44px-plus black primary action and one 44 × 44px wishlist action. Remove compare from homepage cards while retaining it where detailed comparison is useful.
  8. Keep CTA behavior driven by fields already available to the card: “Add to cart,” “Pre-order,” or “Rent.” Retain nopCommerce’s existing product-page redirect when a direct catalog add is not possible.
  9. Keep names, URLs, images, prices, review counts, availability, and action behavior in nopCommerce. Replace sample products in admin after the layout is approved.

Implementation boundary

This file is a wireframe only. No storefront implementation has been changed.

After approval, implementation should remain inside ArityTheme. A theme-owned Views/Shared/Components/HomepageProducts/Default.cshtml, a homepage-specific product-card partial, and Content/css/arity.home-products.css can isolate the new layout from category, search, and related-product grids. Use only fields already present on ProductOverviewModel; do not add per-card service lookups or hardcoded category labels. Register the stylesheet in Views/Home/Index.cshtml. nopCommerce core and admin-managed product data stay untouched.
