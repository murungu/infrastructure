What the live review found

1. The footer publishes nopCommerce’s identity instead of Arity Shop’s

The social buttons point to nopCommerce accounts, and the legal line says “Your store name.” These are admin-data problems, but the current layout gives the store no purpose statement or recognisable brand anchor.

2. Mobile accordion headings are not buttons

“Information,” “Customer service,” and “My account” are clickable h2 elements. They are not keyboard-focusable controls. The closed navigation also keeps ordinary links in the tab order, which can move keyboard focus into clipped content.

3. Several controls are below the Arity touch-target standard

The live social links are 38 × 38px. The newsletter input and button are 36px high. Desktop footer links are about 20px high, and mobile links inside an opened section use a 40px row.

4. Tablet retains a phone layout despite having room

At 768px, all three navigation groups stay collapsed and the footer remains about 787px tall. A two-column layout can expose useful links without creating a dense desktop row.

5. Spacing creates a long footer without adding value

A 100px flex gap separates the collapsed navigation from social content on mobile and tablet. The result is a large empty region before “Follow us” and another long path to the legal content.

6. Desktop uses two unrelated alignment systems

The upper footer uses 95% of the viewport, while the legal row contracts to a fixed 980px wrapper. It no longer aligns with the approved homepage rail used by the hero, categories, and products.

7. The footer gives generic links equal weight

“Apply for vendor account,” “Compare products list,” and other default routes compete with delivery, returns, warranty, product categories, and direct support. The footer should reflect the journeys Arity Shop customers actually need.

8. Newsletter purpose and expectations are unclear

The current form has only a “Newsletter” heading and placeholder. It does not say what customers will receive or set an expectation about privacy and frequency.

Recommended direction to approve

  1. Use a light subscription band above the black footer. Keep the Arity Shop logo on the light surface, add a short benefit statement, and use a visible email label.
  2. Use a 48px email input and black subscription button. Keep validation and success messages next to the form and preserve nopCommerce’s existing newsletter behavior.
  3. Use three navigation groups: “Shop,” “Help,” and “Account.” Populate them from configured store menus and topics rather than hardcoding category IDs or URLs in the theme.
  4. On mobile, use semantic accordion button elements, remove closed lists from the tab order, and give every visible link a 44px row.
  5. At 768px, show support and navigation in a two-column grid. At 1280px, use one support column plus three navigation columns.
  6. Use “Contact us” as the direct support action now. Defer WhatsApp until a real WhatsApp Business destination and an approved theme-owned configuration source both exist.
  7. Render only verified Arity Shop social destinations. Do not publish nopCommerce defaults or empty placeholder channels.
  8. Use the approved rail throughout: 16px mobile gutters, 24px tablet gutters, 32px desktop gutters, and a 1600px wide-screen cap.
  9. Use sentence case, Inter for UI text, black/white surfaces, structural greys, no shadows, no gradients, and no decorative colour. Keep the logo’s red sub-brand dot as the only accent.
  10. Keep copyright, tax/shipping text, topic links, widgets, theme selector, and “Powered by nopCommerce” behavior model-driven. Correct the store name in admin rather than hardcoding it in the view.

Implementation boundary

This file is a wireframe only. No storefront implementation has been changed.

After approval, implementation should remain inside ArityTheme. Theme-owned overrides at Views/Shared/Components/Footer/Default.cshtml and Views/Shared/Components/FooterMenu/Default.cshtml, plus the existing Content/css/arity.footer.css, can provide the new composition and responsive behavior. Keep invoking nopCommerce’s newsletter, social, menu, widget, theme-selector, tax/shipping, and legal behavior where applicable. Use the existing arity.menu.js disclosure helper only if it can provide true button semantics and remove closed content from keyboard navigation; otherwise add a small footer-specific theme script. FooterModel has no support URL, and SocialModel has no WhatsApp field. The first implementation should therefore use nopCommerce’s Contact Us route and render only verified built-in social fields. A future WhatsApp action needs a separately approved theme setting, widget, or other configuration seam. Do not modify nopCommerce core. Do not hardcode store data, category IDs, social destinations, or a WhatsApp number.
